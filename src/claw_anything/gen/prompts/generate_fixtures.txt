## Key Requirements

1. **Cross-service reference consistency**: If an email mentions a customer, that customer must exist in CRM; if a ticket mentions a product, that product must exist in inventory. Email senders should correspond to contacts in the contacts service.
2. **Temporal consistency**: All record timestamps must be strictly within the time window {time_window}. No date may fall outside this range. The causal order of events must be logical (e.g., customer sends complaint email -> ticket is created -> internal discussion meeting notes).
3. **Data realism**: Content must be specific and detailed - do not use "xxx" as placeholders. Amounts, dates, person names, and company names must all be reasonable. All dates in record content (email body text, descriptions, notes) must also be within the time window.
4. **Strict schema compliance**: Each record must include all fields defined in the schema, with field names and types exactly matching.
5. **Strict ID increment**: Use the assigned starting IDs and increment strictly - no skipping numbers.
6. All text content must be in English.

## Output Format

Output in JSON format with the following structure:

```json
{{
  "records": {{
    "gmail": [...],
    "calendar": [...],
    "contacts": [...],
    "todo": [...],
    "kb": [...],
    "inventory": [...],
    "helpdesk": [...],
    "crm": [...],
    "finance": [...],
    "scheduler": [...],
    "rss": [...],
    "config": [...],
    "notes": [...]
  }},
  "thread_record_mapping": {{
    "<thread_name>": {{
      "gmail": ["MSG-xxxx"],
      "crm": ["CUS-xxx"],
      ...
    }}
  }}
}}
```

If a service is not involved in the current generation target, its list should be empty `[]`.
`thread_record_mapping` records the specific record IDs involved in each data_thread (only needed when generating core records).
